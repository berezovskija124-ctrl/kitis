# Новый сайт расписания КИТиС — учебный проект

Сайт расписания колледжа КИТиС для компьютера и телефона. Расписание, группы, преподаватели, аудитории, звонки и итоги всегда на виду. Остальные разделы kitis.ru собраны во вкладке «Меню».

Пары всех 60 групп, 77 преподавателей и 46 аудиторий берутся с сервера расписания колледжа [94.72.18.202:8083](http://94.72.18.202:8083).

> Это учебный проект, а не официальный сайт КИТиС. Аккаунты хранятся только в браузере пользователя и никуда не отправляются.

## Откуда берётся расписание

На сервере колледжа работает программа «Экспресс-расписание». Парсер обходит её страницы:

| Страница сервера | Что из неё берём |
|---|---|
| `cg.htm`, `cp.htm`, `ca.htm` | списки групп, преподавателей и аудиторий |
| `cgN.htm` — «Неделя» группы | актуальное расписание группы на опубликованную неделю |
| `vgN.htm`, `vpN.htm`, `vaN.htm` — «Итоги» группы, преподавателя, аудитории | таблица выполнения нагрузки целиком: преподаватель, группа, подгруппа, дисциплина, тип занятия, всего, план, факт, остаток, план и факт в 1 неделю, окончание, процент выполнения |
| `jN.htm` — «Журнал занятий» | каждая проведённая пара: дата, номер пары, группа, подгруппа, преподаватель, аудитория |

На сайте недели собираются так:

1. **Прошлые недели** — из итогов, то есть из журналов занятий.
2. **Текущая неделя** — из актуального расписания группы («Неделя»). Если «Неделя» на сервере уже переключилась на следующую, текущая неделя берётся из журналов.
3. **Следующая неделя** — из «Недели», если её даты уже стоят на следующую неделю. На кнопке «Следующая неделя» тогда появляется отметка «опубликована».

Какая неделя текущая, сайт определяет по сегодняшней дате в Калининграде. В воскресенье неделя уже закончилась, поэтому сайт сразу открывает новую, если её расписание опубликовано. Дальше последней опубликованной недели листать нельзя: кнопка «Следующая неделя» неактивна. Таймер до конца пары считается по расписанию звонков с kitis.ru.

**«Итоги» на сайте совпадают с сервером.** Для группы, преподавателя и аудитории сайт показывает ту же таблицу, что страницы «Итоги» сервера (`vgN`, `vpN`, `vaN`): те же строки в том же порядке и те же числа, без округления и пересчёта. Рядом есть ссылка «открыть на сервере» на эту же страницу. Часы в таблице академические, как на сервере: одна пара — 2 академических часа, а по времени пара длится 1 ч 30 мин (в понедельник — 1 ч 20 мин). У аудиторий страницы «Итогов» на сервере сейчас пустые, поэтому и на сайте строк нет.

Проверка: `node tests/results-match.js` открывает «Итоги» всех групп и всех преподавателей и сравнивает каждую ячейку с данными сервера.

## Что умеет сайт

- **Расписание** группы, преподавателя и аудитории на неделю, таймер до конца пары, звонки.
- **Итоги** группы, преподавателя и аудитории — как на сервере расписания, ячейка в ячейку.
- **Цвета предметов.** У каждого предмета свой спокойный цвет. На компьютере и на телефоне пара подкрашена в цвет предмета: широкая полоска слева, цветной номер пары и фон, который плавно переходит от цвета предмета слева к белому справа. У «Сейчас идёт» и в «Итогах» — цветная точка. Два предмета никогда не получают один цвет, и цвет предмета не меняется от обновления к обновлению. Цвет новому предмету подбирает робот: свободный, самый непохожий на цвета предметов той же группы и того же преподавателя. Дальше цвет хранится в `data/kitis-data.js` (поле `colors`) и остаётся за предметом, даже если тот на время пропал из расписания. Проверка: `node tests/colors.js`.
- **Избранное** — группы, преподаватели и аудитории. Хранится в этом браузере и показывается первой строкой при выборе расписания. Своя группа из профиля попадает в избранное сама.
- **Поиск** групп, преподавателей и аудиторий; у аудиторий — фильтр «свободные/занятые сейчас».
- **Две версии**: телефон получает мобильный вид, компьютер — полный. В меню есть «Версия для телефона» и «Полная версия сайта»; выбор запоминается до закрытия вкладки, параметров в адресе нет.
- **Разделы kitis.ru внутри сайта**: «Сведения», официальные разделы, страницы студентам, преподавателям и абитуриентам, страница каждой специальности, фотографии.
- **Вход и профиль**, версия для слабовидящих.

В понедельник на сервере 7 «часов»: 1-й — кураторский час «Разговоры о важном» (08:30 – 09:00), со 2-го идут пары по звонкам понедельника (1 пара — 09:10). Пары без аудитории показываются как «Дистант».

Парсер сравнивает новую «Неделю» с прошлой выгрузкой и записывает, у каких групп поменялось расписание. Это видно в кабинете студента и на странице группы.

## Как посмотреть у себя

Распакуйте архив и откройте `index.html` двойным щелчком. Всё работает прямо с диска.

Аккаунты хранятся в браузере (localStorage): своего сервера у сайта на GitHub Pages нет. Вход запоминается на этом устройстве; на другом телефоне нужно зарегистрироваться заново. Чтобы аккаунты были общими для всех устройств, нужна база данных на сервере (например, Supabase или Firebase) — это следующий шаг.

## Материалы и фото с kitis.ru

Официальные разделы и фотографии переносит робот `parser/kitis_sync.py`. Он работает на GitHub каждую ночь, а также сразу после изменения самого робота. Запустить вручную: вкладка **Actions → «Материалы с kitis.ru» → Run workflow**.

- **Разделы.** Робот открывает страницы kitis.ru и оставляет только основную часть: заголовки, текст, списки, таблицы, документы. Меню, шапка и подвал отбрасываются: это ссылки и тексты, которые повторяются почти на каждой странице. Подстраницы раздела добавляются в него же, под своими заголовками. Документы (PDF, DOCX) остаются файлами колледжа и открываются по ссылке. Онлайн-формы (например, электронное обращение) отправляются только на сайте колледжа.
- **Фото.** Снимки новостей, объявлений, мероприятий и фотогалереи копируются в `photos/`. Каждое фото хранится в двух размерах: до 1200 px для просмотра и до 560 px для превью. Значки и баннеры отбрасываются. Если снимок исчез с kitis.ru, при следующем запуске его копия тоже удаляется.
- **Не переносятся** портреты сотрудников со страниц «Сведений» и персональные данные студентов. Подробные сведения о педагогах открываются ссылкой на kitis.ru.
- Если kitis.ru не ответил, на сайте остаются материалы прошлого запуска.

## Безопасность

Сайт проверен атакой на собственную копию: скрипт `tests/attack.js`, 45 проверок (в том числе подменённые материалы с kitis.ru и битые адреса). До исправлений уязвимых мест было 10, после — 0.

- **Строгая CSP** на каждой странице: скрипты только с самого сайта, встроенные обработчики (`onerror=…`) не выполняются, даже если HTML как-то попадёт на страницу. Код страниц вынесен в `js/page-*.js`, `eval` и `new Function` не используются.
- **Ссылки и картинки проверяются** движком страниц: `javascript:`, `vbscript:` и `data:` (кроме картинок) не попадают в `href` и `src`, откуда бы ни пришло значение — из адреса, хранилища или данных сервера.
- **Адрес страницы** (`#group=…`, `#p=…`) читается только по известным ключам, с ограничением длины; битая кодировка и `__proto__` ничего не ломают.
- **Защита от кликджекинга**: внутри чужого сайта (iframe) страница не показывается, только ссылка «Открыть в отдельной вкладке».
- **Пароли**: хранится только соль и хеш PBKDF2-SHA-256 (150 000 итераций). Старые аккаунты переводятся на новый хеш при входе. Пароль — от 8 символов, буквы и цифры.
- **Перебор**: после 5 неверных паролей вход блокируется на 30 секунд, дальше дольше (до 15 минут). Ответ «Неверный e-mail или пароль» одинаковый — по нему нельзя узнать, есть ли аккаунт.
- **Проверка базы при чтении**: подменённые или битые записи в localStorage отбрасываются.
- **Фото профиля**: только JPG/PNG/WebP до 15 МБ; картинка пересобирается в JPEG 320×320, SVG и «картинки» с кодом не принимаются.
- **Удаление аккаунта** — только с паролем.
- **Версии скриптов**: сборка дописывает к адресу каждого скрипта отпечаток файла (`dc-runtime.js?v=…`). Поэтому после обновления сайта браузер не смешает новую страницу со старым скриптом из кэша. Если страница всё же не отрисовалась, `js/guard.js` один раз перезагружает её сам, а потом показывает кнопку «Обновить страницу» вместо пустого экрана.

Ограничения статического сайта: всё, что лежит в браузере, владелец устройства может изменить сам. На `github.io` один адрес у всех сайтов одного пользователя GitHub, поэтому другие его сайты технически видят то же хранилище браузера. Для настоящей защиты нужен серверный вход (Supabase, Firebase или свой сервер).

Сайт показывает настоящее время. Вечером или в воскресенье пар нет, поэтому вместо таймера будет «Следующая пара». Чтобы увидеть, как сайт выглядит во время пары, добавьте к адресу время. Например: `desktop.html?now=2026-11-12T10:30` — четверг, 12 ноября, 10:30, у ИСр24-1 идёт 2 пара. В демо-режиме в верхней полосе написано, какое время подставлено, и есть ссылка на настоящее время. Готовые ссылки есть на странице «О проекте».

## Как выложить на GitHub Pages

1. Войдите на [github.com](https://github.com). Нажмите «+» в правом верхнем углу и выберите **New repository**.
2. Название — например, `kitis-raspisanie`. Видимость — **Public** (на бесплатном аккаунте Pages работает только с публичными репозиториями). Нажмите **Create repository**.
3. На странице пустого репозитория нажмите ссылку **uploading an existing file**.
4. Откройте распакованную папку `kitis-raspisanie`, выделите **всё её содержимое** (файлы и папки `data`, `parser`, `.github`) и перетащите в окно браузера. `index.html` должен оказаться в корне репозитория.
5. Внизу нажмите **Commit changes**.
6. Откройте **Settings → Pages**. В разделе **Build and deployment** выберите *Source:* **Deploy from a branch**, *Branch:* **main** и папку **/ (root)**. Нажмите **Save**.
7. Через 1–2 минуты сверху на той же странице появится ссылка вида `https://ваш-логин.github.io/kitis-raspisanie/`. Её и отправьте преподавателю.

На macOS папка `.github` скрыта в Finder (нажмите Cmd + Shift + . , чтобы её увидеть). Если она не загрузилась, создайте файл вручную: **Add file → Create new file**, в имени напишите `.github/workflows/update-schedule.yml` и вставьте содержимое файла из архива.

### Через командную строку

```bash
cd kitis-raspisanie
git init
git add .
git commit -m "Сайт расписания КИТиС"
git branch -M main
git remote add origin https://github.com/ваш-логин/kitis-raspisanie.git
git push -u origin main
```

Затем включите Pages, как в шаге 6.

## Как обновлять расписание

### Автоматически (GitHub Actions)

После загрузки на GitHub задание «Обновление расписания» запускается каждые 2 часа с 05:17 до 19:17 по Калининграду, с понедельника по субботу. Если на сервере что-то поменялось, задание записывает новый `data/kitis-data.js`, и сайт обновляется сам.

- Запустить вручную: вкладка **Actions** → «Обновление расписания» → **Run workflow**.
- Если задание падает с ошибкой подключения, значит серверы GitHub не могут достучаться до сервера колледжа (он может быть закрыт для зарубежных адресов). Тогда обновляйте одним из способов ниже.
- GitHub отключает задания по расписанию, если в репозитории 60 дней не было изменений. Включить обратно можно во вкладке **Actions**.

### С компьютера (Node.js 18+)

```bash
node parser/update.mjs
```

Скрипт скачает страницы сервера (около 900 страниц, 1–2 минуты) и перезапишет `data/kitis-data.js`. Если расписание не изменилось, файл останется прежним. Затем загрузите `data/kitis-data.js` в репозиторий: **Add file → Upload files** в папке `data`.

### Из браузера, без установки программ

1. Откройте http://94.72.18.202:8083 в браузере.
2. Нажмите F12 и перейдите на вкладку «Консоль» (Console).
3. Вставьте весь текст файла `parser/browser-update.js` и нажмите Enter. Если браузер просит, сначала введите `allow pasting`.
4. Через 1–2 минуты скачается `kitis-data.js`. Загрузите его в папку `data` репозитория, заменив старый.
